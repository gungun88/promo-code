# 后台置顶推广体验优化 PRD

## 1. 背景

后台“置顶推广”表单包含创建按钮、优先级和优惠码选择。优惠码数量较多时，原生下拉框需要长距离滚动，管理员难以快速定位目标优惠码。

## 2. 目标

- 统一创建置顶按钮的上下间距，减少表单底部的视觉跳动。
- 明确优先级规则，降低管理员误解排序方向的风险。
- 支持按优惠码或商户名称过滤候选项，减少大量优惠码中的查找时间。
- 保留现有表单提交、必填校验和键盘操作行为。

## 3. 需求

### 3.1 创建置顶按钮

- 创建按钮使用 `placement-submit-button` 样式类。
- `margin-top: 15px`。
- `margin-bottom: 0`。
- 按钮在保存中、无可用优惠码时保持现有禁用逻辑。

### 3.2 优先级说明

- 优先级继续限制为整数 `0` 到 `1000`。
- 在输入框下方显示小标题：`数值越大，排序越靠前；相同数值按创建时间排序。`
- 说明与后端实际排序保持一致：优先级使用降序排列。

### 3.3 优惠码搜索

- 在优惠码下拉框前增加搜索输入框。
- 搜索同时匹配优惠码和商户名称，忽略大小写和首尾空格。
- 下拉框只展示过滤后的可用优惠码。
- 无匹配项时下拉框为空，但不会破坏原有必填校验。
- 只有“已发布且未下架”的优惠码可进入候选列表。

### 3.4 日期选择

- 开始日期和结束日期使用浏览器原生 `date` 日历控件。
- 只选择年月日，不要求管理员输入时分秒。
- 开始日期必填，结束日期可留空表示长期有效。
- 结束日期不能早于开始日期。

## 4. 非功能要求

- 不改变置顶创建接口字段和后端权限校验。
- 不引入新的第三方依赖。
- 保持桌面端和移动端现有响应式布局。

## 5. 验收标准

- 创建按钮计算样式包含 15px 顶部间距和 0px 底部间距。
- 输入优先级 900 的记录在输入优先级 100 的记录之前展示。
- 输入优惠码或商户名称片段后，候选项实时缩小。
- 输入不存在的关键词时，表单显示无候选项且提交会触发“请选择优惠码”校验。
- 清空搜索词后恢复全部可用优惠码。
- `npm run build` 通过，后端文件语法检查通过。

## 6. 集成测试计划

1. 管理员进入“置顶推广”，确认初始候选项只包含可用优惠码。
2. 输入优惠码片段，确认列表过滤正确并可完成创建。
3. 输入商户名称片段，确认列表过滤正确并可完成创建。
4. 输入不存在的关键词，确认无法提交空优惠码。
5. 创建两个不同优先级的置顶记录，确认高优先级记录排在前面。
6. 清空搜索、刷新页面，确认数据和布局正常。
